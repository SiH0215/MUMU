# MUMU 비교 측정 결과

2026년 11월 20일, 로컬의 `레거시/비교용`과 `리버스`를 같은 입력으로 비교하였습니다. 개인 대화·일기는 사용하지 않고, 가상 대화와 KsponSpeech 평가 음성으로 시험하였습니다.

이번 표본에서는 **답변 길이·출력 토큰 감소**, **한국어 전사 CER 감소**, **다음 대화에서의 사실 회상**을 확인하였습니다. 반면 **입력·전체 토큰 증가**, **Whisper small의 CPU 처리 시간 증가**도 함께 확인하였습니다.

Streamlit·Flask 화면 전체를 브라우저에서 조작한 종단간 시험이 아니라, 각 버전의 실제 대화·STT 핵심 함수를 호출한 시험으로 진행하였습니다. 비교용 함수는 소스에서 추출하여 사용하였으며, 마이크만 동일 음성 파일 재생으로 대체하였습니다. TTS, 브라우저 렌더링과 타이핑 애니메이션, 실제 사용자의 발화 시점은 측정 범위에서 제외하였습니다.

## 2. 답변 길이와 토큰

| 지표 · 응답당 평균 | 비교용 | 리버스 | 관찰 결과 |
|---|---:|---:|---|
| 답변 글자 수 · 공백 포함 | 159.25자 | 43.08자 | 72.9% 감소하였습니다. |
| 출력 토큰 | 95.58 | 25.92 | 72.9% 감소하였습니다. |
| 입력 토큰 | 607.50 | 1660.08 | 173.3% 증가하였습니다. |
| 전체 토큰 · 입력+출력 | 703.08 | 1686.00 | 139.8% 증가하였습니다. |
| 물음표를 포함한 답변 | 12/12 | 7/12 | 매 답변에 물음표가 포함되는 경향이 줄었음을 확인하였습니다. |
| 답변의 물음표 합계 | 32개 | 7개 | 답변에 포함된 질문 수의 차이를 확인하였습니다. |

토큰은 글자 수로 추정하지 않고 API가 반환한 `usage_metadata`로 집계하였습니다. 답변을 짧게 만드는 변화는 확인하였지만, 더 긴 시스템 프롬프트와 현재 시각 등의 지시를 전달하면서 **전체 토큰은 오히려 증가**하였습니다. 입력·출력의 단가가 다를 수 있으므로, 이 합계만으로 실제 청구 금액을 산출하지 않았습니다.

물음표 개수는 문장부호의 단순 집계로 계산하였습니다. 이를 대화의 자연스러움이나 질문 품질 점수로 사용하지 않았습니다.

## 3. 응답 시간

| 서버 측 지표 · 버전당 12건 | 비교용 | 리버스 |
|---|---:|---:|
| 전체 답변 완료 · 평균 | 2.137초 | 1.969초 |
| 전체 답변 완료 · 중앙값 | 1.466초 | 1.238초 |
| 전체 답변 완료 · 최댓값 | 9.474초 | 8.795초 |
| 첫 표시 가능 텍스트 · 평균 | 2.137초 | 1.933초 |
| 첫 표시 가능 텍스트 · 중앙값 | 1.466초 | 1.236초 |

비교용은 답변이 완성되어 반환된 시점을, 리버스는 `on_chunk`에 첫 번째 비어 있지 않은 텍스트가 도착한 시점을 첫 표시 가능 시점으로 측정하였습니다. 브라우저의 폴링·타이핑 시간은 포함하지 않았습니다.

평균·중앙값은 리버스가 짧았지만, 첫 턴 한 쌍을 제외하면 평균이 **1.470초 → 2.012초**로 반대 방향의 결과를 보였습니다. 표본이 작고 네트워크·제공자 대기 시간의 변동도 커서, 이번 결과로 응답 속도의 안정적인 향상을 주장하지 않았습니다.

리버스에서는 첫 텍스트와 전체 완료의 평균 차이가 약 36ms로 작게 나타났습니다. 이처럼 짧은 답변 표본에서는 스트리밍이 첫 표시를 크게 앞당겼다고 판단하지 않았습니다.

API 속도 제한 오류가 1건 발생하여 성공 결과를 보존한 뒤 미완료 요청만 6초 간격으로 재개하였습니다. 오류 응답은 시간·토큰 평균에서 제외하고 별도 기록하였습니다. 대화 시간 측정 일부는 CPU 음성 시험과 실행 구간이 겹쳤으며, 외부 부하를 완전히 통제하지 못하였습니다. 정식 지연 시간 비교에는 단독 실행과 반복 측정을 추가할 필요가 있음을 명시하였습니다.

## 4. 같은 전체 음성의 인식 결과

5초 잘림 효과를 제외하기 위해, 24개 음성의 전체 내용을 두 모델에 모두 전달하였습니다. 모델은 먼저 로드하고 한 번 예열한 뒤 전사 함수의 실행 시간을 측정하였습니다. 비교용 base와 리버스 small의 실제 운영 전사 설정을 사용하였으며, 모델 크기와 디코딩 설정을 각각 독립적으로 분리한 실험으로 해석하지 않았습니다.

| 지표 | 비교용 Whisper base | 리버스 Whisper small |
|---|---:|---:|
| CER | 23.29% · 119/511 | 10.18% · 52/511 |
| 정답과 완전히 일치한 문장 | 1/24 | 8/24 |
| 물음표 누락 · 의문문 12개 | 4/12 | 5/12 |
| 물음표 오삽입 · 평서문 12개 | 0/12 | 0/12 |
| CPU 전사 시간 · 평균 | 1.069초 | 4.729초 |
| CPU 전사 시간 · 중앙값 | 0.764초 | 4.435초 |

이번 표본의 CER은 **13.11%p, 상대적으로 56.3% 감소**하였습니다. 반면 평균 CPU 전사 시간은 약 4.42배로 증가하였고, 물음표 누락도 한 건 증가하였습니다. 따라서 인식 오류 감소와 처리 비용 증가를 함께 기록하였습니다.

CER은 Unicode NFC 정규화 후 공백·문장부호를 제외한 글자 기준으로 `(치환+삭제+삽입)/정답 글자 수`를 계산하였습니다. 물음표는 이 CER에 포함하지 않고 별도 지표로 집계하였습니다. 이 24개 표본 결과를 전체 한국어 음성의 오류율로 일반화하지 않았습니다.

PCM16 파일의 길이가 홀수 바이트인 경우 마지막 불완전한 1바이트만 제외하였습니다. 대상 파일 ID와 전처리 후 SHA-256, 제외한 바이트 수를 측정값에 기록하였습니다.

## 5. 5초 녹음과 VAD 처리 방식 비교

비교용의 실제 녹음 프레임 수에 맞춰 첫 **4.992초**를 사용하고, 짧은 입력은 무음으로 채웠습니다. 비교용 `stt()`의 본문을 실행하여 매번 base 모델을 로드하도록 하였습니다. 리버스는 small 모델을 재사용하고, 실제 `TurnDetector`·Silero VAD로 검출한 구간을 전사하였습니다.

| 첫 LLM 입력의 CER · 원문 전체를 정답으로 비교 | 비교용 · 고정 창+base | 리버스 · VAD+small |
|---|---:|---:|
| 음성 24개 전체 | 40.90% | 21.53% |
| 1.5~4.5초 음성 16개 | 38.43% | 16.59% |
| 5.5~9초 음성 8개 | 42.91% | 25.53% |

고정 녹음 창을 넘는 발화의 뒷부분까지 전달할 수 있음을 확인하였습니다. 이 표에는 모델 변경·음성 길이·디코딩 설정의 효과가 함께 포함되므로, CER 차이를 전부 VAD의 효과라고 해석하지 않았습니다. 비교용은 다음 녹음에서 나머지를 받을 수 있지만, 이미 잘린 첫 구간으로 답변을 요청하므로 본 시험에서는 한 발화를 한 번에 전달하는 경우를 기준으로 비교하였습니다.

리버스는 24개 음성 중 0개에서 발화를 놓쳤으며, 3개는 여러 구간으로 나누어 검출하였습니다. 위 표에서는 양쪽 모두 처음 LLM에 전달하는 한 턴만 사용하였습니다. 여러 VAD 구간의 전사를 모두 이어 붙인 참고 CER은 11.35%였지만, 이를 기존 첫 구간의 CER과 동등한 비교값으로 사용하지 않았습니다. 이 재생 시험에는 구간 사이의 실제 LLM 대기·마이크 일시 정지 시간이 포함되지 않았습니다.

### 불필요한 STT 호출

| 무음 2개·백색 잡음 2개 | 비교용 | 리버스 |
|---|---:|---:|
| STT 호출 수 | 4회 | 0회 |
| 비어 있지 않은 잘못된 전사 | 0/4 | 0/4 |

무음·잡음 표본에서는 **STT 호출 4회를 생략**하였음을 확인하였습니다. 양쪽 모두 잘못된 텍스트를 반환하지 않았으므로, 이번 시험에서는 환각 전사율 개선을 입증하지 않았습니다. 백색 잡음 결과를 생활 소음 전체의 성능으로 확장하지 않았습니다.

비교용에서 매번 발생한 모델 로딩은 평균 0.702초로 측정하였습니다. 리버스의 최초 small 모델 로딩은 2.090초였으며, 이후 재사용하는 구조로 확인하였습니다. 로딩 호출 생략만으로 전체 음성 처리 속도가 빨라졌다고 판단하지 않았습니다.

짧은 음성 16개의 ‘녹음 시작 → 전사 완료’를 재생 시각과 처리 시간으로 추정하면 평균 **7.054초 → 7.285초**로, 이번 CPU 환경에서는 개선되지 않았습니다. 실제 마이크를 켜고 측정한 사용자 체감 지연과는 구분하였습니다.

## 6. 새 대화에서 과거 사실 기억하기

개인 기록 대신 강아지 이름·프로젝트명·좋아하는 보드게임·간식 등 6건의 가상 대화를 실제 로컬 임베딩과 SQLite에 저장하였습니다. 새 세션은 빈 대화 이력으로 시작하였고, 리버스만 현재 코드의 검색 결과를 답변에 전달하였습니다.

| 지표 | 결과 |
|---|---:|
| 표현을 바꿔 물었을 때 관련 사실 검색 | 6/6 |
| 저장 원문으로 재검색 | 6/6 |
| 무관한 질문에서 기록을 잘못 가져온 경우 | 0/6 |
| 검색 시간 · 18회 평균 / 중앙값 | 19.63ms / 19.68ms |
| 첫 저장 · 임베딩 초기화 포함 | 10.241초 |
| 이후 저장 · 5회 평균 | 29.82ms |
| 테스트 DB 크기 · 6건 저장 후 | 64KiB |

실제로 새 대화의 답변까지 생성한 4개 질문에서는 정확한 사실 문자열을 비교용 **0/4**, 리버스 **4/4**에서 확인하였습니다. 답변 원문도 확인하여 단순히 정답 문자열을 부정하는 문장을 성공으로 세지 않았습니다. 같은 세션 안에서 이름을 다시 물은 별도 2개 질문은 양쪽 모두 2/2로 답변하였습니다.

이 차이는 기존 LLM의 지능 차이가 아니라 **다음 세션에 저장 기록을 전달하는 기능 유무**로 해석하였습니다. 데이터 6건과 명시적인 사실 질문만 사용하였으므로, 대규모 기록 검색이나 자유 대화 전체의 기억 정확도가 100%라는 의미로 사용하지 않았습니다.

## 7. 결과에 따라 사용할 수 있는 개선 설명

- 동일 모델을 연결한 대화 시험에서 평균 답변 길이를 약 159자에서 43자로 줄이고, 출력 토큰을 약 73% 줄였음을 확인하였습니다.
- 한국어 평가 음성 24개에서 운영 전사 설정 기준 CER을 23.29%에서 10.18%로 낮췄으며, CPU 처리 시간 증가도 함께 확인하였습니다.
- 고정 길이 녹음 대신 발화 구간을 전사하여 긴 입력의 잘림을 줄이고, 무음·백색 잡음 표본 4개에서 불필요한 STT 호출을 생략하였습니다.
- 로컬 임베딩과 RAG를 적용하여 새 세션의 사실 질문 4개를 모두 회상하였고, 6건의 테스트 DB에서 평균 약 20ms의 검색 시간을 확인하였습니다.

전체 토큰 비용 감소, 안정적인 응답 속도 향상, 물음표 인식 향상, 전체 환경에서의 음성 정확도나 RAG 정확도 향상은 이번 결과만으로 주장하지 않았습니다.

참고로 캐시한 모델 가중치 파일 크기는 base 138.53MiB, small 461.21MiB로 확인하였습니다. 이는 파일 크기이며 실행 중 RAM 사용량을 측정한 값으로 사용하지 않았습니다.
