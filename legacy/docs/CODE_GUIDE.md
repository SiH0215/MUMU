# 해커톤 원본 코드 설명

이 문서는 `IBM-hackathon-program/test`에서 가져온 [레거시 코드](../)를 기준으로 작성하였습니다. 코드의 함수 호출과 저장 흐름을 확인하여 작성하였으며, 당시 외부 서비스의 연결 재검증은 범위에서 제외하였습니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| [main.py](../main.py) | 이미지 기반 홈 화면. 대화와 일기장으로 이동 |
| [pages/chat.py](../pages/chat.py) | 음성 대화, 말풍선 렌더링, 종료 후 전문·일기 저장 |
| [pages/diary.py](../pages/diary.py) | 일기 파일 목록과 제목 표시 |
| [pages/read_diary.py](../pages/read_diary.py) | 선택한 일기의 제목·본문 열람 |
| [mumu.py](../mumu.py) | 콘솔 음성 대화와 전문·일기 저장 |
| [SYSTEMPROMPT.txt](../SYSTEMPROMPT.txt) | 대화 성격과 행동 지침 원본 |
| [DIARYPROMPT.txt](../DIARYPROMPT.txt) | 무무의 1인칭 일기·제목 생성 지침 원본 |
| [img/](../img/) · [pages/img/chat/](../pages/img/chat/) | 홈·일기장 및 대화 화면에서 참조하는 이미지 |

## 홈과 화면 이동

`main.py`에서 홈 이미지를 base64로 변환하여 HTML에 삽입하였습니다. ‘이야기’와 ‘일기장’ 이미지 링크는 각각 `chat`, `diary` 페이지로 연결하였습니다. 또한 `import mumu`를 포함하여 홈 코드를 불러올 때 환경변수·프롬프트·watsonx 모델 초기화도 함께 실행되도록 구성하였습니다.

## 음성 대화의 한 턴

`pages/chat.py`에서 ‘대화하기’를 누르면 다음 처리를 반복하도록 구현하였습니다.

1. `record_audio()`에서 PyAudio 입력을 16kHz·모노·16비트로 5초 녹음하고 float32 배열로 변환하였습니다.
2. `stt()`에서 `whisper.load_model("base")`를 호출하고 `language="ko"`로 전사하였습니다. 모델 로딩 함수는 매 턴 호출하도록 구성하였습니다.
3. 사용자 문장을 `st.session_state.history`에 추가하고 말풍선으로 표시하였습니다.
4. 종료 문구 여부를 확인하고, 일반 발화이면 `chatbot_response()`로 답변을 생성하였습니다.
5. 답변을 같은 이력 항목에 추가하고 화면에 표시한 뒤 `speak()`로 음성 출력하였습니다.
6. 음성 재생이 끝나면 다음 녹음을 시작하도록 구성하였습니다.

VAD 기반 발화 감지 대신 고정 길이 녹음을 사용하였습니다. 마이크 입력과 음성 재생은 Streamlit 서버를 실행한 컴퓨터에서 처리하였습니다.

## LLM 요청과 대화 이력

모델은 `meta-llama/llama-4-maverick-17b-128e-instruct-fp8`을 사용하였습니다. 최대 생성 토큰은 900으로 설정하고 `<|eot|>`를 종료 시퀀스로 전달하였습니다.

`build_prompt()`에서 시스템 프롬프트 → 이전 사용자·무무 발화 → 현재 입력 → assistant 헤더 순서로 문자열을 구성하였습니다. 응답은 `results[0]['generated_text']`에서 추출하여 `<|eot|>` 이후를 제거하였으며, 화면 버전에서는 ‘무무 >>’, ‘assistant:’ 같은 말머리도 제거하였습니다.

| 버전 | 다음 답변에 전달하는 기록 |
|---|---|
| `pages/chat.py` | 현재 화면 세션에 누적한 이력 |
| `mumu.py` | 현재 콘솔 대화의 전체 이력 |

화면 버전에서는 현재 발화를 이력에 먼저 추가한 뒤, `build_prompt()`에 현재 입력으로도 전달하였습니다. 이로 인해 해당 발화가 요청에 두 번 포함되는 부분을 확인하였으며, 보관본에서는 원본 동작을 유지하였습니다.

과거 세션의 `log_DB` 파일을 다음 대화에 전달하거나 임베딩·벡터 검색으로 참조하는 기능은 당시 구현 범위에서 제외하였습니다.

## Supertone 합성과 재생

`speak()`에서 `https://supertoneapi.com/v1/text-to-speech/{VOICE_ID}`로 요청하였습니다. 한국어, `Sad` 스타일, `sona_speech_1`, WAV 형식, 속도 1.1을 설정하였습니다. 음성 Content-Type 응답은 임시 WAV로 저장한 뒤 pygame으로 재생하였습니다.

요청 타임아웃, 재생 후 임시 파일 삭제, JSON 음성 URL 응답 처리는 원본에 미구현된 항목으로 확인하였습니다. 보관 과정에서도 원본에 없던 예외 처리나 자원 정리는 추가 구현 대상에서 제외하였습니다.

## 대화 종료와 일기 저장

종료 문구는 인식된 문자열과 정확히 비교하도록 처리하였습니다. 화면 버전의 루프가 끝나면 다음 저장 처리를 수행하도록 구현하였습니다. STT·답변 처리 오류로 루프를 빠져나간 경우에도 저장 코드에 도달할 수 있음을 확인하였습니다.

1. `get_next_indexed_filename()`에서 폴더의 기존 번호를 확인하여 다음 파일명을 결정하였습니다.
2. 전체 세션 이력을 `log_DB/log_번호.txt`에 저장하였습니다.
3. `summarize_conversation()`에서 일기 프롬프트와 전체 이력을 같은 watsonx 모델에 전달하였습니다.
4. 요약 결과를 `diary_DB/diary_번호.txt`에 저장하였습니다.

원본 일기 프롬프트에는 무무가 ‘나’로, 상대를 ‘너’로 부르며 3~4문장의 일기를 작성하고 마지막 줄에 3단어 이하 제목을 쓰도록 지시하였습니다. 별도 감정 분류 모델 대신 일기 프롬프트를 통한 요약 방식을 사용하였습니다.

## 일기 조회

`pages/diary.py`에서 `diary_DB`의 텍스트 파일을 수정 시각의 내림차순으로 정렬하였습니다. 마지막 3개의 비어 있지 않은 줄에서 ‘제목:’을 찾고, 없으면 마지막 줄을 제목으로 사용하였습니다.

`pages/read_diary.py`에서 `file` 쿼리의 파일명을 `os.path.basename()`으로 처리하여 일기 폴더에서 조회하였습니다. 제목과 본문을 분리하고 HTML 문자를 이스케이프하여 표시하였습니다. 전문 로그를 말풍선으로 다시 보는 화면은 당시 구현 범위에서 제외하였습니다.

## 보관 기준

홈과 음성 대화·일기장에 필요한 Python 파일 5개, 프롬프트 2개, 이미지 13개를 보관하였습니다. 파일 내용은 원본 그대로 유지하였으며, 사용하지 않는 별도 대화 버전·실험 코드·이미지는 제외하였습니다.

`main.py`에서 `import mumu`를 실행하므로 `mumu.py`를 유지하였습니다. 또한 `pages/chat.py`의 `find_asset()`이 페이지 폴더 아래의 이미지를 먼저 조회하므로 `pages/img/chat/`의 이미지 2개도 유지하였습니다.

`requirements.txt`에는 보관 코드가 사용하는 Python 패키지를, `.env.example`에는 환경변수 이름만 기록하였습니다. 실제 API 키와 대화·일기 파일은 보관 대상에서 제외하였습니다. 외부 서비스 연결 검증은 수행 범위에서 제외하였습니다.
